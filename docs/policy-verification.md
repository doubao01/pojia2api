# 策略库使用与验证

## 已接入的使用流程

1. 首页 → 策略管理 → 新建策略。
2. 填策略名称、绑定模型（半角/全角逗号或换行分隔）与正文；不绑定模型表示通用策略。
3. 保存后返回列表，开关独立启停。策略写入本机存储成功后才发布界面快照。
4. 供应商页的账号行 → 策略，可以选择固定绑定，或选择“不固定，按模型自动匹配”。
5. 从文件导入会把文本/Markdown预填成草稿，用户确认保存后才进入策略库。
6. 我的 → 导出配置包含设置、账号和策略。旧备份没有 `policies` 字段时，不会清空当前策略库。

## 匹配和注入

- 固定绑定优先；停用或已删除的固定策略不回落到通用策略。
- 不固定时精确模型命中优先，通用策略兜底；每次请求只应用一条。
- 故障转移从原始请求体重新应用当前账号策略，不叠加上一账号的内容。
- chat 注入为独立 system 消息，保留客户端原有消息。
- 注入器还支持 responses 的 instructions，以及 messages 的 system 文本/内容块数组，保留原内容块和缓存标记。
- **当前网关只开放 chat HTTP 路径**。另外两种注入器通过单元测试，不代表已经实现对应 HTTP 协议入口。
- 策略库本机保存；匹配的策略正文随请求发给用户配置的上游，不向其他服务同步。

示例策略（没有真实密钥或账号）：

```json
{
  "id": "brief-answer",
  "name": "简洁回答",
  "models": ["demo-1"],
  "instruction": "使用简洁的中文回答。",
  "enabled": true,
  "builtin": false
}
```

## 自动验证与边界

- AccountPersistenceTest 对所有凭据类型执行编码→解码往返，含账号固定绑定；修复前已复现缺少 Credential 序列化器。
- PolicyTest 覆盖精确/通用/停用/固定匹配、三种正文注入、原内容块保留。
- PolicyGatewayTest 使用回环 HTTP 服务确认 chat 路径返回实际响应，检查上游接收到策略及客户端消息；也验证固定绑定和故障转移。
- 回环测试使用受控测试供应商，不验证任意真实外部供应商或登录协议。
- Android 界面、文件选择器、进程重启和保存失败恢复仍需要 Android 仪器测试/真机验收，不能以 CI 编译替代。

- 通用 WebView 读到 Cookie 不证明授权成功，也不能用于不同域的官方 API。
- 任务/额度页、前台服务与界面共享运行状态、开机自启接收器和真正的悬浮球仍待实现/验收。
- 请求重试、超时、去指纹等设置必须核实实际转发接线，不能只以设置页出现为完成。
- 原版参考来源目前主要是 3.9.3 反编译代码；3.10.0差异与真实屏幕仍待核对。
- 自研实现不得把原作者署名作为自己的作者信息；可保留原项目参考署名。
