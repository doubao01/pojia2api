# 策略库使用与验证

## 已接入的使用流程

1. 首页 → 策略管理 → 新建策略。
2. 填策略名称、绑定模型（半角/全角逗号或换行分隔）与正文；不绑定模型表示通用策略。
3. 保存后返回列表，开关独立启停。策略写入本机存储成功后才发布界面快照。
4. 供应商页的账号行 → 策略，可以选择固定绑定，或选择“不固定，按模型自动匹配”。
5. 从文件导入会把文本/Markdown预填成草稿，用户确认保存后才进入策略库。
6. 我的 → 导出配置包含设置、账号和策略。旧备份没有 `policies` 字段时，不会清空当前策略库。

## 匹配和注入

- 固定绑定优先；停用或已删除的固定策略不回落到通用策略。
- 不固定时精确模型命中优先，通用策略兜底；每次请求只应用一条。
- 故障转移从原始请求体重新应用当前账号策略，不叠加上一账号的内容。
- chat 注入为独立 system 消息，保留客户端原有消息。
- 注入器还支持 responses 的 instructions，以及 messages 的 system 文本/内容块数组，保留原内容块和缓存标记。
- 网关已开放 chat、responses、messages 三个 HTTP 入口；策略注入分别写入独立 system 消息、`instructions` 和 `system`，保留客户端原有内容。
- 策略库本机保存；匹配的策略正文随请求发给用户配置的上游，不向其他服务同步。

示例策略（没有真实密钥或账号）：

```json
{
  "id": "brief-answer",
  "name": "简洁回答",
  "models": ["demo-1"],
  "instruction": "使用简洁的中文回答。",
  "enabled": true,
  "builtin": false
}
```

## 自动验证与边界

- `AccountPersistenceTest` 对所有凭据类型执行编码→解码往返，含账号固定绑定；修复前已复现缺少 Credential 序列化器。
- `PolicyTest` 覆盖精确/通用/停用/固定匹配、三种正文注入、原内容块保留。
- `PolicyGatewayTest` 使用回环 HTTP 服务确认 chat 路径返回实际响应，检查上游接收到策略及客户端消息；也验证固定绑定和故障转移。
- 设备授权测试覆盖 Qoder 21 个、WorkBuddy 20 个契约用例；Loomy SMS 协议新增 5 个用例。
- `AccountArchiveTest` 覆盖 3.10.0 WorkBuddy 单对象 `{account,auth}`、原版账号数组 `provider/uid/nickname/secret`、原生 Account 往返和损坏文件。
- `ClientFingerprintStripperTest` 覆盖去指纹开关关闭 / 开启、内容块数组、解析失败回退；清理范围按 3.10.0 dex 文案限为对话内容里的计费头、Claude Code / Codex 身份句、模板句、空模板参数。
- `WireProtocolGatewayTest` 覆盖 `/v1/responses` 与 `/v1/messages` 的请求转换、响应格式、策略注入位置及非法 JSON。
- 最近一次 JVM 回归：core 72、providers 46，失败 0。
- GitHub Actions run #20（提交 `45ad59c`）：内核测试 success，Debug APK 构建 success。
- 回环测试使用受控测试供应商，不验证任意真实外部供应商或登录协议。
- Android 界面、文件选择器、悬浮球权限、开机广播、进程重启和保存失败恢复仍需要 Android 仪器测试/真机验收，不能以 CI 编译替代。

## 当前已接入的应用功能

- 设置页：端口、局域网监听、访问密钥、失败阈值、冷却、重试、请求超时、日志上限、开机自启、悬浮球、去掉客户端指纹（请求正文清洗）、配置导入导出、重置统计、关于。
- 供应商页：WebView Cookie 登录、Qoder/CodeBuddy 设备授权 WebView 与轮询、Loomy 两步短信 UI/协议、OAuth/手动添加、账号导入导出（兼容原版账号数组与 WorkBuddy 单对象）、连通性检测、本机端口扫描。
- 首页：运行状态、复制地址、访问密钥、请求/成功率/耗时/模型/缓存/token 统计、账号/策略/任务额度入口。
- 日志页：清空日志。
- 应用与前台服务共享同一个 `GatewayRunner`，避免界面状态与实际监听状态分离。

## 仍未完成或受限的范围

- Loomy 生产签名材料没有复制原 APK 内嵌秘密；当前公开构建默认显示“签名材料未配置”，需要由安全构建环境显式注入后才能真实发短信。
- 任务/额度页已存在并明确显示供应商接口未提供，但具体供应商签到、任务和额度接口尚未实现。
- 通用 WebView 读到 Cookie 不证明授权成功，也不能用于不同域的官方 API；真机登录仍需用户实际操作验收。
- 原版参考来源主要是 3.9.3 反编译代码；3.10.0 差异与真实屏幕仍待逐屏核对，当前不能宣称视觉 1:1。
- 自研实现不得把原作者署名作为自己的作者信息；可保留原项目参考署名。
